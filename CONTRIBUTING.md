# Contributing

This repository uses a lightweight workitem convention to keep issues useful and discoverable.

## Workitem basics

- Minimal required fields for every issue: type, title, description
- Every workitem must include at least one label. Use the expanded taxonomy: type (bug/feature/idea), priority (priority-high/priority-medium/priority-low), and area (area-*) labels. Use `scale-epic` to mark large umbrella items.

## Who can create and label workitems

- Only maintainers may set labels and create workitems. If you need a new label, open a discussion or contact a maintainer.

### Bug reports

- Required: clear reproduction steps and severity (Low/Medium/High).
- Use the provided Bug Report template (.github/ISSUE_TEMPLATE/bug_report.md).

### Feature requests

- Required: user story and acceptance criteria.
- Use the Feature Request template (.github/ISSUE_TEMPLATE/feature_request.md).

### Triage

- Triage is performed on-demand by maintainers. Use the `needs-triage` label to flag items.

### Workflow notes

- Keep issues small and focused; large efforts should be tracked with `scale-epic` and child issues.
- Use cross-references to link related work and PRs.

If you have questions about this policy, open an issue and tag a maintainer.
